## ✅ What's Working (Production-Ready)

### 1. Evidence Annotations - COMPLETE
**All endpoints support evidence with sanitized echo:**

- `/v1/run` ✅
- `/v1/optimise` ✅
- `/v1/run_bundle` ✅
- `/v1/run_timeslices` ✅

**Functionality:**
- Validates evidence (node_id, source, note, weight)
- Sanitizes before echo (removes notes for privacy)
- Echoes in `meta.evidence_applied`
- Records count in audit logs

**Example:**
```typescript
// Request
{
  graph: { ... },
  evidence: [
    { node_id: "demand", source: "survey_2024", note: "Q3 data", weight: 0.8 }
  ]
}

// Response
{
  schema: "run.v1",
  summary: { ... },
  meta: {
    evidence_applied: [
      { node_id: "demand", source: "survey_2024", weight: 0.8 }
      // Note: 'note' field removed for privacy
    ]
  }
}
```

### 2. Timeslices Endpoint - COMPLETE

**`/v1/run_timeslices` fully functional:**

- ✅ Up to 12 timeslices per request
- ✅ Per-slice node/edge overrides
- ✅ Priors validation (validation-only, see below)
- ✅ Evidence validation and echo
- ✅ Deterministic with seed
- ✅ Response includes model_card and optional meta

**Example:**
```typescript
POST /v1/run_timeslices
{
  graph: { nodes: [...], edges: [...] },
  timeslices: ["Q1", "Q2", "Q3", "Q4"],
  slice_overrides: [
    { slice: "Q2", nodes: [{ id: "demand", value: 1.2 }] }
  ],
  evidence: [
    { node_id: "demand", source: "forecast_2024" }
  ],
  seed: 4242
}

// Response
{
  schema: "run_timeslices.v1",
  results: [
    { slice: "Q1", summary: { p10, p50, p90 }, confidence: 0.85 },
    // ... more slices
  ],
  model_card: {
    seed: 4242,
    response_hash: "abc123...",
    timeslices_count: 4
  },
  meta: {
    evidence_applied: [
      { node_id: "demand", source: "forecast_2024" }
    ]
  }
}
```

## ⚠️ Known Limitation: Priors (Validation-Only)

### Status
**Priors are validated but NOT applied to inference in v1.6.0**

### What Works
- ✅ API accepts priors parameter
- ✅ Validates format (number or distribution)
- ✅ Validates range (0-1)
- ✅ Validates node existence
- ✅ Returns 400 on invalid priors

### What Doesn't Work
- ❌ Priors don't influence inference results
- ❌ Results are identical with or without priors

### Why
**Design limitation** - The inference engine architecture doesn't support priors:
- `InferenceConfig` interface doesn't include priors
- Inference engines don't apply priors to node beliefs
- Requires major feature addition (2-3 days)

### Transparency
**Clearly documented in:**
- `RELEASE_NOTES_v1.6.0.md` - Section header warns "API-Ready, Inference Pending"
- `CRITICAL_FINDINGS.md` - Comprehensive analysis
- `README.md` - Updated with limitation note

### User Impact
- Users can send priors without errors
- API contract is stable (won't break when functional support added)
- Clear expectation: priors don't affect results in v1.6.0

### Roadmap
**v1.7.0** - Functional priors implementation:
1. Extend `InferenceConfig` with priors field
2. Implement prior application in inference engines
3. Add tests verifying priors influence results
4. Remove "validation-only" caveats from docs
